# Lingo 正式版 1.0.0 综合审查

日期：2026-11-02。范围：网页交互、富文本替换、后台请求、凭据生命周期、权限、依赖、许可证、隐私与商店材料。默认免解锁与此前确定的产品范围保持不变。

## 已修复的问题

| 级别 | 问题与触发条件 | 修复和验证 |
|---|---|---|
| P1 | 密码 Key 尚未解锁时切换到仅本次会话，会移除唯一持久副本。 | 跨模式转换前必须解锁或填写新 Key；回归确认失败转换保留原 vault。 |
| P1 | 已注入的内容脚本可能在站点授权撤销后仍存在，后台原先没有逐请求重新核对浏览器访问权。 | 发请求前由 Chrome scripting 验证发送者的当前 documentId/框架访问权；权限移除时停止现有请求。模拟 Chrome 拒绝访问时，API 请求计数不增加，恢复授权后可重试。 |
| P2 | 未填写 Key 时不能保存语言；自动凭据损坏时，撤销数据同意也被凭据错误阻挡。 | 普通设置可独立保存，保留现有损坏副本供用户决定恢复或删除；撤销同意有效。 |
| P2 | 密码派生期间与站点暂停/恢复并发，旧 settings 会覆盖新的站点状态。 | 所有设置写入共用串行队列；用延迟密码派生复现并验证并发恢复站点不会丢失。 |
| P2 | 锁定/删除后，设置页尚未保存的 Key 或密码输入仍留在 DOM 中。 | 成功锁定/删除/保存后清空相关输入并恢复密码遮蔽；对应 UI 回归通过。 |
| P2 | 富文本网站同步修改原生插入结果时，浮窗仍无条件显示替换成功。 | 替换后核对实际文本，考虑 Chrome 的换行和 NBSP 表示；不一致时提示检查编辑区及撤销。 |
| P2 | 在解锁密码框按 Enter 会提交设置而非解锁。 | Enter 显式执行解锁，避免误提交，UI 回归通过。 |

前四项中的凭据删除、空 Key 保存、并发覆盖，以及凭据输入清理，均在修复前的定向回归中实际失败；Enter 问题也复现后修复。授权拒绝与网站二次改写采用受控模拟验证，不冒充用户日常 Chrome 中的实际撤权/第三方网站全覆盖。

## 验证结果

- TypeScript 检查和生产构建通过。
- 12 项核心测试、45 项浏览器流程、25 项凭据生命周期、7 项本轮定向回归通过（共 89 项）。另有生产 manifest 加载检查。
- npm audit 未报告当前依赖树的已知漏洞；这不等于证明没有未知漏洞。
- 当前发布文件与全部可达 Git 历史执行凭据模式扫描；未发现真实 Key，仅有白名单内明确无效的测试 fixture。扩展运行 ZIP 不含此 fixture。
- UI/API 回归均用隔离 Chrome 和模拟 API；本轮未读取真实 Key、调用真实 OpenAI API 或操作私人 Gmail 内容。早期真实 API/Gmail 记录见 LIVE-CHROME-GMAIL.md。

## 商店材料与版本一致性

- 正式版统一为 1.0.0。设置页版本从实际 manifest 读取，避免再手写旧版本。
- 四张 1280×800 商店图全部由本次正式构建重新生成，逐张目视检查；设置页照片显示 1.0.0、默认免解锁与当前语言界面。
- 翻译/写作图中的文本和 API 输出是明确标注的演示样例；未使用私人邮件。截图副本仅额外授予本地演示站点权限，UI 代码与 dist 相同。
- BUILD-PROVENANCE.json 记录当前运行文件与图片 SHA-256。打包脚本验证版本、来源构建、图片哈希、尺寸、MIT License 和第三方声明。已用临时副本验证：旧版本截图或截图生成后发生代码变更，都会拒绝打包。
- 隐私政策与商店文案保持一致：默认自动 AES-256-GCM 加密、本机非导出 CryptoKey、可选密码加密、用户同意后才发 API、无自动全站授权、无开发者中转服务。

## 仍然存在的边界与上架事项

1. 自动解密能力也在本机浏览器配置中，不能抵御完整配置窃取或已被控制的系统，不等同于系统钥匙串。按用户决定保留为默认；密码模式可选。
2. 简单 Gmail/标准输入和富文本已覆盖；复杂图片、表格、框架编辑器等仍保守提供复制。没有对所有网站或当前日常 Gmail 重新做人工验收。
3. 模型可用性、余额与输出质量取决于用户的 OpenAI 项目。本轮不重复消耗真实 API 额度。
4. 商店尚未提交。用户完成注册/付款；如审核需要测试凭据，应单独提供限用途测试访问，不把个人 Key 放入公开仓库、商店文案或 ZIP。
5. 本次是工程审查与自动回归，不是独立渗透测试或审核通过承诺。
