# Lingo 1.0.0-dev.8 验证记录

2026-11-02 · Chrome 数字版本 0.9.7 · 私有开发预览。

第一版兼容范围：普通网页划词保留浮窗；Google Docs、已知 PDF URL 和浏览器受限页面优先显示侧边栏入口。右键翻译统一进入侧边栏（包括可编辑区域），不依赖网页浮窗注入。其他不能提供选区的页面仍可从插件菜单打开侧边栏粘贴。Google Docs 内容脚本不创建浮窗；专项适配只保留在 ROADMAP 的未来可选目标。

侧边栏首次打开、清除以及接收新选区时，原文编辑框默认展开；手动折叠后再接收选区会重新展开。普通浮窗仍保留原来的原文折叠行为。

- TypeScript、21 项单元检查、43 项隔离功能检查及最终生产构建通过。
- 功能回归覆盖空白面板、PDF 选区、新选区重新展开、编辑原文、翻译/写作、三种语言、Docs 菜单侧边栏优先及失败提示；API 使用拦截响应。
- 本机 Chrome 已加载 dev.8，Docs 菜单没有浮窗/网页授权按钮，侧边栏原文输入框默认展开。
- 本机 Chrome 原生 PDF 中先折叠原文框，再通过公开 Sample PDF 的右键“用 Lingo 翻译”发送 534 字符测试选区，确认输入框重新展开并显示完整原文，实际翻译响应进入同一侧边栏。此检查使用现有配置；没有读取或输出 Key。
- 4 张商店草稿图与最终构建匹配；开发包 22 个运行文件，不包含 Google Docs 实验探针。密钥审计未发现凭据候选。

网站仍可阻止取得选区，这类情况使用侧边栏粘贴。URL 识别不能穷举所有无 .pdf 后缀的文件，PDF 右键与通用侧边栏入口不依赖该识别。不承诺在 Google Docs 自动读取或替换文字。
